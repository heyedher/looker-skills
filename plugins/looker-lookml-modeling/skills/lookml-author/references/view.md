# LookML Views & Derived Tables (`*.view.lkml`)

This reference covers standard LookML views, extensions, refinements, Native Derived Tables (NDTs), and SQL Derived Tables (SDTs).

## 1. File Organization & Naming Conventions

- **Standard Views:** `views/[datasource]/[view_name].view.lkml` (`snake_case`)
- **Extended Views:** `views/[datasource]/[view_name]_ext.view.lkml`
- **Refinements:** `views/[datasource]/[view_name]_rfn.view.lkml`
- **Native Derived Tables (NDTs):** `views/[datasource]/[view_name]_ndt.view.lkml`
- **SQL Derived Tables (SDTs):** `views/[datasource]/[view_name]_sdt.view.lkml`

---

## 2. Core View Standards

1. **Explicit `sql_table_name`:** Required on all standard table-backed views (e.g., ``sql_table_name: `project.dataset.users` ;;``). Never rely on implicit table-name defaults.
2. **Primary Key First (`primary_key: yes`):** Every view (including NDTs and SDTs) **must** define a unique primary key as its first dimension with `primary_key: yes`. Looker requires this to compute [symmetric aggregates](https://cloud.google.com/looker/docs/symmetric-aggregates) and prevent fanout duplication across joins.
3. **Refinements (`+view_name`) vs. Extensions (`extends`):**
   - Use **Refinements** (`view: +users`) to layer fields, labels, or descriptions onto an existing view in place without creating a new view name.
   - Use **Extensions** (`extends: [users]`) to create a new specialized view inheriting from a base view.

---

## 3. Derived Tables: Evaluate Native Derived Tables (NDT) First

When creating entity rollups or aggregated fact tables (e.g., `user_order_facts`), **always evaluate whether a Native Derived Table (`explore_source`) can be used before writing a raw SQL Derived Table (`sql`)**:

- **Why Prefer NDTs (`explore_source`):**
  1. **Single Source of Truth:** Reuses existing dimensions and measures from the source Explore instead of duplicating SQL logic.
  2. **Automatic Row-Level Security (RLS):** Automatically inherits `access_filter` and `required_access_grants` defined on the underlying Explore.
  3. **Compile-Time Safety:** Validator catches broken field references immediately if underlying column names change.
- **When to Use SDTs (`sql`):**
  Use raw SQL Derived Tables when the query requires database-specific window functions (`RANK() OVER (...)`, `LEAD()`), recursive CTEs, complex `UNION ALL` chains, or tables not yet exposed in an Explore. Add a brief comment explaining why an SDT was chosen.
- **Persistence (PDTs):**
  Pair materialized derived tables with `datagroup_trigger` and warehouse clustering/indexing (`cluster_keys` on BigQuery/Snowflake; `indexes` on Redshift/Postgres).

---

## 4. Examples

### Standard Table-Backed View

```lookml
view: users {
  sql_table_name: `project.dataset.users` ;;

  dimension: user_id {
    primary_key: yes
    type: number
    sql: ${TABLE}.id ;;
    group_label: "IDs"
    description: "Unique internal user identifier."
  }

  dimension: email {
    type: string
    sql: ${TABLE}.email ;;
    description: "User primary email address."
  }
}
```

### Persistent Native Derived Table (NDT) Entity Rollup (Recommended)

```lookml
view: user_order_facts {
  derived_table: {
    datagroup_trigger: ecommerce_etl
    cluster_keys: ["user_id"]
    explore_source: order_items {
      column: user_id {}
      column: lifetime_orders { field: order_items.count_orders }
      column: lifetime_revenue { field: order_items.total_sale_price }
    }
  }

  dimension: user_id {
    primary_key: yes
    type: number
    hidden: yes
    description: "Unique ID of the user. Clustered key for high-performance joins."
  }

  dimension: lifetime_orders {
    type: number
    description: "Total lifetime orders placed by the user."
  }

  dimension: lifetime_revenue {
    type: number
    value_format_name: usd
    description: "Total lifetime revenue generated by the user."
  }

  dimension: lifetime_orders_tier {
    type: tier
    tiers: [1, 2, 3, 5, 10]
    style: integer
    sql: ${lifetime_orders} ;;
    description: "Cohort tier based on lifetime order count."
  }
}
```

### Persistent SQL Derived Table (SDT) with Window Function

```lookml
# SDT used because RANK() OVER window function is not expressible via explore_source
view: user_session_ranks {
  derived_table: {
    datagroup_trigger: ecommerce_etl
    cluster_keys: ["user_id"]
    sql:
      SELECT
        session_id,
        user_id,
        session_start_time,
        RANK() OVER (PARTITION BY user_id ORDER BY session_start_time) AS user_session_index
      FROM `project.dataset.events`
      WHERE event_type = 'session_start' ;;
  }

  dimension: session_id {
    primary_key: yes
    type: string
    sql: ${TABLE}.session_id ;;
    description: "Unique session identifier."
  }

  dimension: user_id {
    type: number
    hidden: yes
    sql: ${TABLE}.user_id ;;
    description: "Foreign key to users."
  }

  dimension: user_session_index {
    type: number
    sql: ${TABLE}.user_session_index ;;
    description: "Chronological rank of the session for a given user."
  }
}
```
